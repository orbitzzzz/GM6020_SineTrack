# GM6020 正弦速度/位置跟随（RoboMaster 开发板 C 型）

电控组第二次作业：用 GM6020 电机分别跟随正弦变化的速度曲线和位置曲线，并用独立看门狗（IWDG）做失联/死机保护。

- MCU：**RoboMaster 开发板 C 型，STM32F407IGH6**（168 MHz，1MB Flash / 128KB RAM）
- 电机：DJI GM6020，**CAN1，1 Mbps**
- 控制周期：1 ms（TIM2 更新中断）
- 曲线：速度正弦 200 rpm / 0.3 Hz；位置正弦 180° ± 88° / 0.3 Hz
- 看门狗：IWDG 2.0 秒，`config.h` 里默认开启
- 调试输出：USART1（C 板 4-pin UART2）115200，VOFA+ JustFloat

> 这是按“实验室的 C 板”移植的版本。C 板自带 CAN 收发器，不需要外接 TJA1050/SN65HVD230 模块。
> 如果到了实验室发现用的不是 C 板，先不要烧录，回来告诉我板子型号。

| 东西 | 说明 |
|---|---|
| RoboMaster 开发板 C 型 | 实验室提供，自带 CAN1/CAN2 收发器 |
| GM6020 电机 | 实验室提供，电机 ID 默认 1 |

- **SWD**：接 DAPLink
- **24V 输入**：XT30 接口，8~28V

## 二、接线

```
   24V 电源                         RoboMaster C 板
  ┌─────────┐                      ┌──────────────────┐
  │ 24V +   ├─────────────────────►│ 24V 输入         │
  │ 24V -   ├──┬──────────────────►│ GND              │
  └─────────┘  │                   │                  │
               │                   │ CAN1 口          │
               │                   │  CAN_H ◄─────────┼──── GM6020 CAN_H
               │                   │  CAN_L ◄─────────┼──── GM6020 CAN_L
               │                   │                  │
               └───────────────────┴──────────────────┘
                        （24V 负极、C 板 GND、电机 GND 必须共地）
```

要点：

1. **C 板自带 CAN 收发器**，CAN_H/CAN_L 直接接 C 板的 CAN1 口，不要再外接收发器。
2. **CAN_H/CAN_L 不要接反**。电机线颜色以实验室线材标签为准（一般红黑是 24V，黄绿是 CAN）。
3. **共地**：24V 电源负极、C 板 GND、电机 GND 必须接在一起。
4. **120Ω 终端电阻**：CAN 总线两端各 120Ω。C 板上通常有终端电阻跳线/焊盘，问一下实验室的板子是否已经使能；短距离台架测试至少保证总线两端各有一个 120Ω。
5. **24V 只接电机和 C 板的 24V 输入**，绝对不能接到 3.3V/5V 引脚。
6. 电机 24V 大电流建议走实验室的功率分配板，不要长期从 C 板的小电流通路取电；按实验室标准接线来。
7. DAPLink 的 SWDIO/SWCLK/GND/3.3V 接 C 板 SWD 口。

### 串口看波形

C 板 4-pin UART（丝印 **UART2**）：

```
USB-TTL 的 RX  ──►  C 板 UART2 的 TX（PA9）
USB-TTL 的 GND ──►  C 板 GND
（USB-TTL 的 TX 不用接；5V 也不要接）
```

- 波特率 **115200**。
- C 板的 TX 是 3.3V 电平，USB-TTL 选 3.3V 电平最稳。
- 如果实验室的 4-pin UART 线序不同，以板子丝印/原理图为准，只接 **TX 和 GND** 两根即可。

## 四、看曲线（二选一）

### 方案 A：VOFA+（推荐，最直观）

1. 打开 VOFA+，选择 USB-TTL 的串口，波特率 **115200**。
2. 协议选择 **JustFloat**，通道数 **5**。
3. 5 个通道依次是：

| 通道 | 含义 | 单位 |
|---|---|---|
| 0 | 参考速度 | rpm |
| 1 | 实际速度 | rpm |
| 2 | 参考位置 | ° |
| 3 | 实际位置 | ° |
| 4 | 模式 | 0=速度，1=位置 |

4. 电机上电、程序运行后就能看到波形。
5. 程序默认 **15 秒速度模式 + 15 秒位置模式自动交替**：
   - 通道 4 = 0 时，截“速度跟随曲线”（通道 0 和 1）；
   - 通道 4 = 1 时，截“位置跟随曲线”（通道 2 和 3）。
6. 用 `Win + Shift + S` 截图，保存好。

> 位置曲线的参考值在 180° 上下摆动（约 92°~268°），实际值应该贴着参考值走。

### 方案 B：Ozone（没有 USB-TTL 时）

1. 用 Ozone 打开 `build/GM6020_SineTrack_C.elf`，选择 DAPLink/CMSIS-DAP。
2. 在 `Watched Data` / `Data Sampling` 里添加：

```
g_dbg_ref_speed
g_dbg_act_speed
g_dbg_ref_pos
g_dbg_act_pos
g_dbg_mode
```

3. 全速运行，采样频率 50~100Hz。
4. 按 `g_dbg_mode` 区分：0 截速度，1 截位置。

> Ozone 对第三方 DAPLink 需要许可证（SEGGER 可申请非商业免费版）。
> 如果 Ozone 连不上，优先用 VOFA+ + USB-TTL。

## 六、控制原理（答辩重点）

### 1. 速度模式

```
参考速度 = 200 * sin(2π * 0.3 * t)          [rpm]
电压 = 前馈(90 * 参考速度) + PID(参考速度, 实际速度)
```

- 前馈：按 GM6020 大约 13.3 rpm/V 的转速常数，估算“维持这个转速需要多少电压”。前馈把大部分电压先给到位，PID 只修剩下的误差，所以跟随曲线更贴。
- PID：P=150，I=150，D=0。积分负责消除稳态误差，输出限幅 ±24000（对应约 ±19.2V）。

### 2. 位置模式（位置环 + 速度环串级）

```
参考位置 = 4096 + 2000 * sin(2π * 0.3 * t)   [编码器计数，8192=360°]
位置误差 = wrap(参考位置 - 实际角度)          [折算到 ±4096，处理跨圈]
速度指令 = 0.3 * 位置误差 + 位置参考的导数(前馈)
电压     = 90 * 速度指令 + 速度PID(速度指令, 实际速度)
```

- 外环只用一个 P（0.3），内环是速度 PID。
- 位置参考的导数作为速度前馈：参考本身在动，先把“应该有的速度”喂给内环，外环只修偏差，所以位置跟随的相位滞后很小。
- `wrap()` 把误差折算到 ±4096：比如参考 10、实际 8190，直接相减是 -8180，折算后是 +12，电机知道应该往正方向走一点，而不是反向转一圈。
- 速度指令限幅 ±250rpm，防止从速度模式切到位置模式时猛冲。

### 3. 为什么用 1ms 控制周期

- GM6020 官方建议控制帧 1ms 发一次；
- 1kHz 对 0.3Hz 的正弦来说有 3000 多个采样点，足够平滑；
- TIM2 更新中断，优先级 0，保证控制周期不被其它中断打断。

### 4. CAN 协议

发送（电压控制）：

| 电机 ID | 标准帧 ID | 数据 |
|---|---|---|
| 1~4 | 0x1FF | 4 个 int16，小端；ID n 占第 (n-1)*2 字节 |
| 5~7 | 0x2FF | 同理 |

int16 范围 -30000~30000，对应 -24V~+24V。

接收（反馈）：

| 帧 ID | 数据 |
|---|---|
| 0x204 + 电机 ID | data[0:1] 角度（大端）、data[2:3] 转速 rpm（大端）、data[4:5] 电流、data[6] 温度 |

> 注意：**发控制帧是小端，收反馈帧是大端**，这是 DJI 的协议规定，代码里分别处理了。

## 七、看门狗（作业要求）

`config.h`：

```c
#define IWDG_ENABLE     1      // 默认开启
#define IWDG_PRESCALER  64
#define IWDG_RELOAD     999
```

F407 的 LSI 约 32kHz，所以超时时间：

```
T = 64 × (999 + 1) / 32000 = 2.0 秒
```

喂狗策略在 `control.c` 的 `Control_1ms()` 末尾：

```c
if (IWDG_FEED_ALWAYS ||
    (s_tick < MOTOR_STARTUP_GRACE_MS) ||
    Motor_IsOnline())
{
    HAL_IWDG_Refresh(&hiwdg);
}
```

- 正常运行时，每 1ms 喂一次；
- 如果 **CAN 断线 / 电机掉电 / 程序卡死**，`Motor_IsOnline()` 变 0，就停止喂狗；
- 2 秒后芯片复位；复位后电机收不到控制帧，GM6020 自己也会停转——**双重保护**；
- 上电前 2 秒是宽限期，等电机上线；
- 调试时如果不想让它一直复位，把 `IWDG_FEED_ALWAYS` 改成 1。

### 怎么现场演示看门狗

1. 正常运行，电机跟着正弦转；
2. 拔掉 CAN 线（或关掉电机 24V）；
3. 大约 2 秒后板子复位（LED 状态/串口数据会重新开始）；
4. 插回 CAN 线，系统重新上线。

> 不接电机时，程序会在上电约 2 秒后周期性复位，这是正常保护逻辑。
> 在家里空板测试时，可以把 `IWDG_FEED_ALWAYS` 临时改成 1。

## 八、参数怎么改（都在 `Tasks/inc/config.h`）

| 想改什么 | 改哪个宏 |
|---|---|
| 速度正弦幅值/频率 | `SPEED_SINE_AMP` / `SPEED_SINE_FREQ` |
| 位置正弦幅值/频率/中心 | `POS_SINE_AMP` / `POS_SINE_FREQ` / `POS_CENTER` |
| 固定只跑速度/位置 | `CONTROL_MODE` 改成 `MODE_SPEED` / `MODE_POSITION` |
| 自动切换时间 | `MODE_SWITCH_MS` |
| 电机 ID | `MOTOR_ID` |
| PID | `SPEED_KP` / `SPEED_KI` / `POS_KP` |
| 关看门狗 | `IWDG_ENABLE 0` |
| 关串口输出 | `VOFA_ENABLE 0` |

调参顺序（如果现场曲线不好看）：

1. 先只跑速度模式，`SPEED_KI` 先给 0，慢慢加 `SPEED_KP`，直到响应快但不抖；
2. 再加 `SPEED_KI`，消除稳态误差；
3. 位置模式主要调 `POS_KP`，太大电机会来回晃，太小跟随会滞后。

## 九、实验室考核步骤（照着做）

1. **接线前断电**，检查 24V 正负极、CAN_H/CAN_L、共地。
2. 确认电机接在 **CAN1**（不是 CAN2），C 板 CAN1 口有终端电阻。
3. 用 DAPLink 的 SWD 接 C 板，烧录程序。
4. 打开 VOFA+（115200，JustFloat，5 通道）。
5. 给电机上 24V，观察是否收到反馈：
   - VOFA+ 的实际速度/位置有变化（用手轻轻拨动电机，通道 1/3 会动）→ 通信正常；
   - 一直是 0 → 查 CAN 线、120Ω、24V、电机 ID。
6. 确认反馈正常后，观察电机是否跟随正弦：
   - 如果电机往一个方向猛冲/顶死 → **立刻断电**，把 `POS_DIR` 改成 `-1` 再试；
   - 如果方向对但抖 → 减小 `SPEED_KP`；
   - 如果跟不上 → 适当增大 `SPEED_KI` 或 `POS_KP`。
7. 等曲线稳定，按模式分别截图：
   - 速度：参考速度 vs 实际速度；
   - 位置：参考位置 vs 实际位置。
8. 拔 CAN 线演示看门狗复位（如果老师要求）。
9. 代码上传 GitHub，仓库设为 **public**，把链接发给组长。

## 十、常见问题

**Q1：完全收不到电机反馈？**
- CAN_H/CAN_L 接反；
- 电机没上 24V；
- 没有共地；
- 电机 ID 不是 1（改 `MOTOR_ID`）；
- 没接 120Ω 终端电阻；
- 电机插在 CAN2，但代码用的是 CAN1（PD0/PD1）；
- C 板 CAN1 收发器/终端电阻没有使能（问实验室）。

**Q2：有反馈但电机不转？**
- 控制帧 ID 不对（ID 1~4 用 0x1FF）；
- 电压值一直是 0（检查 `Motor_IsOnline()`、`g_motor.rx_count`）；
- 电机处于保护/故障状态（重新上电）。

**Q3：电机转但方向反了/位置环飞车？**
- 立刻断电，把 `POS_DIR` 从 `1.0f` 改成 `-1.0f`。

**Q4：曲线毛刺大？**
- 速度反馈分辨率是 1rpm，低速时会有量化毛刺，属正常；
- 适当减小 `SPEED_KP`，或把正弦频率降到 0.2Hz。

**Q5：程序下载后一直复位？**
- 没接电机时 IWDG 会每约 2 秒复位一次，这是保护逻辑；
- 调试时把 `IWDG_FEED_ALWAYS` 改成 1。

**Q6：VOFA+ 收不到数据？**
- 串口选错/被占用；
- 波特率不是 115200；
- 接的是 C 板 UART2 的 TX（PA9），不是 RX；
- USB-TTL 和 C 板没有共地；
- 协议不是 JustFloat、通道数不是 5；
- `VOFA_ENABLE` 被改成 0 了。

**Q7：烧录失败？**
- DAPLink 的 SWD 线序/供电；
- `flash.bat` 里 `IDE_ROOT` 和实际 CubeIDE 安装路径不一致；
- C 板没上电（SWD 的 3.3V 只能参考，板子还是要供电）。

## 十一、答辩可能问的问题（背下来）

1. **为什么用 CAN，不用 PWM？**
   GM6020 是带内置驱动的电机，只能通过 CAN 发控制帧；PWM 是给裸电机/电调用的。

2. **CAN 波特率怎么算的？**
   APB1 = 42MHz，预分频 3 得到 14MHz，一位 = 1+9+4 = 14 个时间片，14MHz/14 = 1Mbps。

3. **C 板的 CAN1 用哪两个引脚？**
   PD0 = CAN1_RX，PD1 = CAN1_TX，复用 AF9；不是 PA11/PA12。

4. **GM6020 控制帧是什么？**
   ID 1~4 用标准帧 0x1FF，8 字节里放 4 个 int16 电压值，小端，范围 ±30000 对应 ±24V。

5. **反馈帧怎么解析？**
   ID = 0x204 + 电机 ID；角度、转速、电流都是大端；角度 0~8191 对应 0~360°。

6. **为什么发帧小端、收帧大端？**
   DJI 协议就是这样规定的，代码里分别用移位处理。

7. **为什么 1ms 控制一次？**
   GM6020 官方建议 1ms 发一帧；1kHz 对 0.3Hz 正弦足够，控制也及时。

8. **速度环怎么做的？**
   正弦参考 + 前馈 + PI；前馈按转速常数估算电压，PI 修正误差。

9. **位置环怎么做的？**
   位置 P 外环 + 速度 PI 内环的串级；位置参考的导数做速度前馈；误差用 wrap 处理跨圈；速度指令限幅。

10. **为什么位置环只用 P？**
    积分由内环速度 PI 承担；外环加 I 容易在换向/跨圈时积分饱和，反而不好调。

11. **编码器跨圈怎么处理？**
    角度误差折算到 -4096~+4096，走最短方向。

12. **看门狗怎么配置的？超时多少？**
    IWDG 预分频 64、重装载 999，F407 的 LSI 约 32kHz，超时 2 秒；`config.h` 默认开启。

13. **为什么不是无条件喂狗？**
    无条件喂狗只能防程序跑飞，防不了 CAN 断线/电机掉电；这里只在“控制循环在跑且电机反馈正常”时喂狗，失联就复位，复位后电机也会停，形成双重保护。

14. **喂狗放在哪里？**
    TIM2 的 1ms 中断里，控制循环末尾。

15. **F407 的 168MHz 怎么来的？**
    HSE 12MHz，PLLM=6 → 2MHz，PLLN=168 → 336MHz VCO，PLLP=2 → 168MHz；APB1 四分频 42MHz，APB2 二分频 84MHz。

16. **TIM2 的 1ms 怎么算？**
    APB1 定时器时钟 84MHz，PSC=83 → 1MHz，ARR=999 → 1kHz 更新中断。

17. **串口发数据会不会影响控制？**
    用中断发送，24 字节一帧，100Hz；上一帧没发完就丢帧，不阻塞 1ms 控制循环。

18. **如果电机 ID 是 3 怎么办？**
    改 `config.h` 的 `MOTOR_ID 3`，反馈帧和 0x1FF 里的字节位置会自动对应。

19. **如果电机转向和位置环相反？**
    改 `POS_DIR -1`。

20. **代码里哪个文件最重要？**
    `control.c`（正弦/PID/喂狗）、`motor.c`（CAN 协议）、`config.h`（参数）。
